★ 4.6.20260830 更新（hotfix）：
  - 修复导入分组/服务器 id 漂移：分组表、服务器表使用 AUTOINCREMENT，导入时按
    导出 id 显式插入却未重置 sqlite_sequence，导致新增 id 与导出冲突（例如导出
    id=4 但当前序列已到 6，导入后新增分组拿到 id=6，与导出数据错乱、server 的
    parent_id 指向错误）。现导入前先 truncate 整表并重置自增序列，再按导出 id
    严格恢复，后续自动新增 id 紧接其后、不再漂移（B77）。

★ 4.5.20260830 更新（hotfix）：
  - 修复安装到 C:\Program Files 后启动报错「PermissionError: [WinError 5]
    拒绝访问」：日志目录此前回退到只读的程序目录下的 logs，现默认回退到
    %LOCALAPPDATA%/ServerRemoteInfoManager/logs，避开系统保护目录（B74）。
  - 修复分组导出缺少 id：此前仅导出 name/parent_id，导入后重新分配 id 导致
    server 的 parent_id 错乱、分组归属混乱；现已导出 id 并按 id 重建父子关系（B75）。
  - 修正服务器导出密码策略：B73 导出密文在跨机器/跨用户导入时会解密失败、密码
    置空；现改为导出明文（保留安全确认弹窗），导入时由目标机 add_server 重新
    加密，跨机器迁移正常（B76）。

★ 4.4.20260830 更新（hotfix）：
  - 修复 VNC viewer / Radmin 连接窗口不显示：两者同为 GUI 程序，仍被 B67 的
    隐藏参数（SW_HIDE）误隐藏，连接后窗口不出现；已移除其隐藏参数，仅 cmdkey
    等控制台程序保留隐藏（B72，同 mstsc 的 B67 修正）。

★ 4.3.20260830 更新（hotfix）：
  - 修复「导入服务器」失败报错「InfoServer object has no attribute
    'init_servers_data'」：import_server 导入成功后刷新服务器树时误调用了不
    存在的方法（UI 层方法名为 init_server_data），已改回正确方法名（B71）。

★ 4.2.20260830 更新（hotfix）：
  - 修复「导出分组 / 导出服务器」报错「name 'sqlite3' is not defined」：S1
    密码加密重构时 export_server 改写直接 sqlite3.connect() 但文件顶部未
    import sqlite3，导致导出功能无法使用；已在 Object/infoServer.py 顶部
    补充 import sqlite3（B70）。

★ 4.1.20260830 更新（hotfix）：
  - 修复 RDP 连接后远程桌面窗口打不开的问题：4.0.20260830 为消除 cmdkey
    黑框新增的隐藏参数（SW_HIDE）被误用到 GUI 程序 mstsc.exe，导致远程桌面
    窗口被整体隐藏；本次启动 mstsc 时移除隐藏参数，仅对 cmdkey 保留隐藏，
    凭据清理/写入不再黑框闪烁，且远程桌面窗口可正常显示（B68）。

【不兼容改动】
--------------------------------------------------------------------------------
1. RDP 连接流程调整为：清理旧凭据 → 写入凭据 → 生成临时 .rdp（仅含
   高级选项配置与连接地址，不含密码）→ mstsc 执行 → 会话关闭后自动
   清理凭据与临时文件。连接体验不变，远程桌面高级选项随连接自动生效。
2. 服务器树密码列默认脱敏显示（*********），查看明文需选中行后右键
   "显示密码"。
3. 数据目录变更：数据库 data.db 与日志 logs/ 由"程序所在目录"改为
   用户目录 %LOCALAPPDATA%/ServerRemoteInfoManager/（Program Files
   只读，旧版在该目录写数据会失败）。已发布的 exe 版本数据自动存放于此；
   源码运行时仍沿用项目根目录。
4. 密码存储改为加密：主机密码与「运维智脑」模型密钥不再以明文存入数据库，
   由 tools/secret.py 统一加密（DPAPI 优先、Fernet 回退）。旧版明文数据在
   首次启动时被自动迁移加密，无需手动处理；升级后数据文件须保持一致，
   跨机器/跨用户直接拷贝数据库可能导致已加密内容无法解密。
